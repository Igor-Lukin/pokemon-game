1. ЦЕЛЬ И ГРАНИЦЫ ФАЗЫ 1
--------------------------------------------------------------------
ЦЕЛЬ: игрок в бою с ДИКИМ покемоном может бросить покебол; при удаче дикий
ловится и попадает в команду (или в питомник, если команда полна); бол
тратится; при неудаче дикий делает свой ход.

ФАЗА 1 = плоский множитель бола (обычный/Great/Ultra/Master различаются ЧИСЛОМ).
Схему проектируем так, чтобы условные болы добавились позже без ломки.

НЕ ДЕЛАЕМ в фазе 1 (это отдельный HANDOFF, фаза 2):
  - условные болы (Net ×по типу, Dusk ночью, Quick 1-й ход, Timer по ходам,
    Heavy по весу, Love по полу, Repeat по «уже пойман») и КАРТОЧКА-форма бола
    (по образцу attack_form.html);
  - анимация «3 покачивания»;
  - магазин/валюта, ягоды, held-предметы, камни эволюции.
Владелец подтвердил именно такой объём.

5. ФОРМУЛА ЛОВЛИ (фаза 1 — простая, без покачиваний)
--------------------------------------------------------------------
Дано: MaxHP, HP=CurrentHP дикого; baseRate=pokemons.catch_rate;
      ballMult=items.catch_multiplier/100; statusMult по статусу дикого.
  statusMult: сон(5)/заморозка(4) = 2.5; паралич(2)/ожог(3)/яд(6,7) = 1.5; иначе 1.0.
Значение:
  a = ((3*MaxHP - 2*HP) * baseRate * ballMult * statusMult) / (3*MaxHP)
Исход:
  - если a >= 255  -> ГАРАНТИРОВАННО поймал;
  - иначе шанс = a/255, один бросок rand (в [0,1)); < шанс -> поймал, иначе провал.
Считать в целых аккуратно (float для statusMult/ballMult ок; a — float, сравнить с 255).
Формулу вынести в отдельную функцию (напр. catchChance(...)) для будущей фазы-2.
