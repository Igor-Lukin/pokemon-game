BACKEND (новый файл + маршруты):
  server/handlers/api/online.go — НОВЫЙ:
    - Константы-ручки: onlineWindow=5*time.Minute, challengeTTL=45*time.Second.
    - Presence считается на лету из users.last_seen+location_id (то же правило
      онлайна, что в [7]: last_seen < 5 мин UTC, strftime). Своей таблицы НЕТ.
    - Эфемерные вызовы в памяти: map challenges (ключ "challengerID-targetID") +
      challengeMu (mutex), как battleSessions. Отдельная init()-горутина
      cleanupChallenges чистит протухшие (>TTL). Плюс инлайн-чистка в incoming/
      outgoing поллингах.
    - 5 эндпоинтов (все JSON, auth по сессии):
      GET  /api/location/players     -> [{user_id, username}] онлайн на моей
                                        локации, кроме меня, ORDER BY username.
      POST /api/challenge {target_user_id} -> гарды §3: не себя; цель онлайн И на
                                        той же локации; нет активного дубля на пару.
                                        400 с внятной причиной иначе.
      GET  /api/challenge/incoming   -> pending-вызовы мне [{challenger_id,
                                        challenger_name}] (протухшие чистятся).
      POST /api/challenge/respond {challenger_id, accept} -> declined/accepted;
                                        на accept дёргает серверную заглушку
                                        startPvpBattle(challengerID, targetID).
      GET  /api/challenge/outgoing   -> {status: none|pending|accepted|declined,
                                        target_name}; терминальный статус — чистим.
    - startPvpBattle(challengerID,targetID) СТАБ (серверный): только log.Printf +
      вызов уже помечен accepted (обе стороны увидят по поллингу). TODO(Часть B).
  server/routes/routes.go — +5 маршрутов рядом с /api/* (перед /api/locations/{id}).
