0. КАК РАБОТАЕМ (ритм — НЕ менять)
--------------------------------------------------------------------
Владелец НЕ программист: простой язык, маленькие проверяемые шаги.
Машина диалога — RDP-сервер, проект на проброшенном диске
(\\tsclient\d\pokemon-game, у владельца D:\pokemon-game). На RDP Go НЕТ —
компилировать нельзя. НО Python + sqlite3 ЕСТЬ. Поэтому:

  РАБОТА С БД (схема/данные)  -> делаем ПРЯМО на RDP через Python (проверяемо тут же).
  РАБОТА С Go (код)           -> агент ПРАВИТ .go на диске, но НЕ компилирует.
                                Проверяет владелец на ОСНОВНОМ ПК (там Go):
                                go build ./server + go vet + сверка поведения,
                                дописывает отчёт. Владелец говорит «отчёт готов».

Ритм: одна связная порция -> свой TEST_*.txt в корень -> проверка. Порядок
блоков A -> B -> C -> D (см. §5–8), не забегать.

ГРАБЛИ (соблюдать всегда):
- ПЕРЕД каждой правкой БД — бэкап рядом: pokemon.db.bak-before-<что>
  (напр. pokemon.db.bak-before-gender, ...-before-attract). Боевая БД —
  database/pokemon.db (файл pokemon.db в КОРНЕ — пустышка 0 байт, не он).
- Python: sys.stdout.reconfigure(encoding='utf-8'); запускать через Bash-heredoc,
  НЕ через PowerShell (BOM ломает stdin).
- Атаку включаем (disabled=0) ТОЛЬКО когда она реально работает.
- Файлы .go — UTF-8, не ломать русские строки/комментарии.

1. КОНТЕКСТ
--------------------------------------------------------------------
Браузерная игра: Go + SQLite + серверный HTML. Кампания по атакам (см.
HANDOFF_moves.txt — соседний файл, справочно) закрыта на disabled=10, где 2 из
остатка — гендерные атаки, не сделанные из-за отсутствия пола. Эта задача
добавляет пол (разблокирует их) и заводит «букву привлекательности» A/B/C под
будущее спаривание.

Важно из HANDOFF_moves (сигнатуры, изменённые кампанией — НЕ сломать):
  applyEffectByID(bs, ...)          — bs ПЕРВЫМ параметром;
  applyStatChanges(...)             — через него идут изменения статов;
  applyHeal(healer, snatcher, ...)  — snatcher 2-м;
  calculateDamage(bs, ...)          — bs ПЕРВЫМ.
  Диспетчер статусных ходов: handleCustomStatusMove(bs, attacker, defender, ...)
  — у него ЕСТЬ и атакующий, и цель, и bs (нам это нужно для гейта по полу).
  Уникальная механика = КОД (карта по id в профильном модуле), НЕ data-driven.
