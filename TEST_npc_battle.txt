ЧТО СДЕЛАНО (по §-разделам ТЗ)
--------------------------------------------------------------------

§6 БД (бэкап database/pokemon.db.bak-before-npcbattle):
  - server/db/database.go: +CREATE TABLE npc_pokemons (npc_id, pokemon_id, level,
    position). Та же таблица применена к живой БД.
  - Тест-данные в живой БД:
      * Ричи (id=1): team_mode='random', team_size=3, min_level=8, max_level=12.
      * Тренер Ли (id=2, локация 2, team_mode='fixed', size=2): диалог (старт-узел
        + опция «Сразимся!» action='battle' + «Не сейчас» action='close'),
        ростер: Бульбазавр lv10 (pos0), Чармандер lv12 (pos1).

§5 wild.go — вынесено ЯДРО генерации:
  - buildGenerateFor(pokemonID, level) *WildPokemonGenerate: база статов вида ->
    IV/натура/статы/generateWildMoves. Используется и диким боем, и командой NPC.
  - generateWildPokemon теперь = выбрать вид из локации + ролить ур.1-20 +
    buildGenerateFor. Поведение диких НЕ менялось (сверить regression!).

§4 battle.go — команда врага через «указательный трюк» (без переписывания движка):
  - BattleState: +EnemyTeam []BattlePokemon, +EnemyActiveIdx int, +TrainerName.
    WildPokemon ВСЕГДА указывает на активного врага = &EnemyTeam[idx]. Срез строим
    один раз, НЕ append-им; смена врага = только индекс + переустановка указателя.
  - BattleResponse: +EnemyCount, +EnemyRemaining, +TrainerName (индикатор отряда).
  - buildPlayerTeam(userID) — общий хелпер сборки команды игрока, зовётся из
    StartBattleHandler И TrainerBattleStartHandler (одна точка правды).
  - Оба victory-места заменены на handleEnemyFaint:
      * MoveHandler (~2219): allEnemyDown -> "victory" (awardExp ТОЛЬКО для wild);
        enemySwitched -> "enemy_switch"; player.IsFainted -> need_switch/defeat.
      * SwitchHandler (~2450, обморок врага от остаточного урона на входе игрока):
        для "trainer" враг сменяется и бой продолжается (новый враг атакует ниже);
        для "wild" — "victory" как раньше (БЕЗ awardExp — сохранено исходное
        поведение SwitchHandler, там опыт и не начислялся).
  - fillEnemyIndicator(bs,&resp) добавлен в ответы move/switch/switch_done.

§4.2/§5 npc_battle.go (новый):
  - TrainerBattleStartHandler: auth -> {npc_id} -> npc-настройки -> buildPlayerTeam
    -> buildNPCTeam -> BattleState{BattleType:"trainer", WildPokemon:&EnemyTeam[0]}
    -> погода по npc.location_id -> BattleResponse{Type:"start", +индикатор}.
  - buildNPCTeam: 'fixed' из npc_pokemons (порядок position,id); 'random' —
    team_size случайных видов, уровни [min,max]; пустой fixed -> фолбэк на random.
    Гарантия >=1 боеспособного, иначе 400.
  - handleEnemyFaint: для "wild" враг пал = конец; для "trainer" — следующий живой
    (с применением ловушек его стороны через applyEntryHazards; если входящий пал
    от ловушек — берём следующего), лог «<Тренер> отправляет <имя> в бой!».
  - routes.go: +POST /api/battle/trainer/start.
  - Ловля: catch.go уже режет BattleType!="wild" — тренерская ловля запрещена сама.

§7 Админка (admin/npc.go + admin/npc_team.go + npc_form.html):
  - DeleteNPC: +каскад DELETE FROM npc_pokemons.
  - NPCFormData: +Roster, +AllPokemons; loadNPCRoster / loadAllPokemons.
  - CRUD ростера: /admin/npc/team/{add,edit,delete} (checkAdmin, валидация вида и
    level>=1, возврат на страницу редактирования).
  - npc_form.html: секция «Ростер команды (fixed)» показывается при team_mode=fixed
    (список строк вид/уровень/позиция + add/edit/delete). Блок «Команда для боя»
    (random) — уровни/размер уже сохранялись потоком A.

§8 Фронт (game.js / game.css):
  - startTrainerBattle(npcId): реальный POST /api/battle/trainer/start -> startBattle
    (переиспользован рендер боя). Ошибки -> alert текстом сервера.
  - performMove: обработка "enemy_switch" (перерисовка карточки врага, «ВАШ ХОД»);
    тренерская "victory" -> «Вы победили тренера <имя>!» без опыта/эволюции.
  - performSwitch: карточка врага перерисовывается целиком (враг мог смениться от
    остаточного урона на входе) + индикатор.
  - updateEnemySquad(count, remaining): «шарики» отряда врага у карточки NPC (живые
    красные, павшие серые); для дикого боя индикатор снимается. game.css: стили.

ОСТАТКИ / ПОГРАНИЧНЫЕ СЛУЧАИ (MVP, не баги — согласовано ТЗ §4.4/§10)
--------------------------------------------------------------------
  - Фазинг врага командой NPC (игрок бьёт Рыком/Вихрем по врагу): оставлен no-op
    (для одиночки так и было). Смена врага по фазингу — не делаем в MVP.
  - Двойной обморок за ход в тренерском бою (игрок КО врага И сам падает от
    отдачи): отдаём need_switch; карточка нового врага освежится при следующей
    смене игрока. Косметика, не влияет на логику победы.
  - SwitchHandler-победа над диким от остаточного урона: опыт НЕ начисляется (как
    и в исходном коде — намеренно сохранено, чтобы не менять поведение дикого боя).
