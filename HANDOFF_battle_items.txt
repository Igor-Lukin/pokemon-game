1. ЦЕЛЬ, РЕШЕНИЯ ВЛАДЕЛЬЦА, ГРАНИЦЫ
--------------------------------------------------------------------
ЦЕЛЬ: покемон может НОСИТЬ предмет; у предмета есть ТИП; если тип предмета
совпадает с типом покемона-носителя — атаки носителя усиливаются. Это первый
надеваемый предмет — заодно строим саму механику «held».

РЕШЕНИЯ ВЛАДЕЛЬЦА (по ним и делаем):
  - ЭФФЕКТ (типовой гейт): усиление включается, ТОЛЬКО ЕСЛИ тип предмета == тип
    покемона (у двутипного — совпадение с ЛЮБЫМ из двух типов). При совпадении —
    плоский множитель урона ко ВСЕМ урон-атакам носителя (любого типа атака).
    Если типы не совпали — предмет не даёт эффекта (множитель 1.0).
  - ОБЪЁМ: полный, с UI надевания (игрок надевает/снимает из инвентаря).

УТОЧНЕНИЕ ПО ЭФФЕКТУ (взято буквальное прочтение «усиливает атаки покемона»):
  при совпадении типов усиливаются ВСЕ урон-атаки носителя, НЕ только атаки того
  же типа. (Если позже захотим «только атаки совпадающего типа» — это лёгкая
  правка условия, см. §5.)

ВАЖНАЯ ПОПРАВКА ПО КОДУ (проверено): в формуле урона НЕТ зарезервированной
переменной под усилитель — есть только stab (1.0/1.5 по совпадению типа АТАКИ)
в battle.go ~483-491 и итог на строке ~536. Мы добавляем ОТДЕЛЬНЫЙ множитель
heldMult (со своим, ИНЫМ гейтом — по типу ПОКЕМОНА), stab не трогаем. Механики
надетого предмета не существует вообще (нет столбца в user_pokemons, нет поля у
BattlePokemon, у items нет типа) — это и есть основная работа.

НЕ ДЕЛАЕМ сейчас (позже, отдельные HANDOFF):
  - другие held-эффекты (ягоды-в-бою, восстановление, шанс-эффекты, статы);
  - held у диких; снятие предмета атаками (Knock Off/Trick); расходуемые held.
  Пока held не тратится в бою.

5. НЮАНС ГЕЙТА (прочитать, чтобы сделать РОВНО это)
--------------------------------------------------------------------
Гейт — по типу ПОКЕМОНА, НЕ по типу атаки:
  срабатывает, если pokemonHasType(носитель, предмет.type_id).
Это НЕ настоящий STAB (там гейт по типу атаки). При срабатывании усиливаются ВСЕ
урон-атаки носителя (эффект типо-НЕзависим на уровне атаки; ограничение — только
на входе, по типу покемона).
  - Двутипный носитель: совпадение с ЛЮБЫМ из двух типов -> эффект есть.
  - Если ПОЗЖЕ захотим «усиливать только атаки того же типа» (двойной гейт:
    покемон И атака этого типа) — добавить в условие ещё move.TypeID ==
    attacker.HeldItemTypeID. СЕЙЧАС НЕ делаем.

8. ГРАБЛИ / РИСКИ
--------------------------------------------------------------------
  - Дефолт множителя = 1.0, НЕ 0 (иначе урон обнулится). Гейт по pokemonHasType.
  - Множитель брать у ТЕКУЩЕГО attacker (после смены покемона активный несёт свой
    HeldItemTypeID/HeldAtkMult — грузится при построении команды).
  - effect_value — множитель ×100 (как catch_multiplier). type_id — тип предмета,
    NULL/0 у не-типовых.
  - Множитель применяется ТОЛЬКО в calculateDamage (урон-путь). stab, статусные
    ходы, эффективность — не трогать.
  - Надеть/снять/свап меняют user_items — ПОД ТРАНЗАКЦИЕЙ.
  - Один held на покемона (held_item_id одиночный). Надевание при занятом слоте = свап.
  - Go на RDP нет: правки + БД (python/utf-8/bash-героку/бэкап). Отчёт -> TEST_helditems.txt.
