TEST_evolution_conditions — детерминированные развилки эволюции
Дата: 2026-10-23

ЗАДАЧА
Убрать недетерминированные упрощения в развилках:
- Иви(133) -> Эспеон(196) / Умбреон(197) — вместо двух одинаковых friendship-веток
  введено условие времени суток.
- Тайрог(236) -> Хитмонли(106) / Хитмончан(107) / Хитмонтоп(237) — сравнение
  Atk/Def на момент эволюции.

СХЕМА / МИГРАЦИЯ
- pokemons.evolution_condition TEXT — код условия (пусто = условие не задано).
- pokemons.evolution_priority INTEGER DEFAULT 0 — приоритет при нескольких
  подходящих ветках (больше = раньше).
- Миграция идемпотентная: server/db/database.go -> migrateEvolutionConditions().
  Правит строку только пока condition пустой, поэтому правки из админки не затираются.

ПОДДЕРЖАННЫЕ УСЛОВИЯ
- time_day    — серверное локальное время 06:00–19:59
- time_night  — серверное локальное время 20:00–05:59
- atk_gt_def  — Attack > Defense (расчётные статы на целевом уровне)
- atk_lt_def  — Attack < Defense
- atk_eq_def  — Attack = Defense
- fairy_move  — у экземпляра выучена атака типа Fairy (18)

ДАННЫЕ В АКТИВНОЙ БД
- 196 Эспеон:   from=133, method=4 (friendship), condition=time_day,   priority=0
- 197 Умбреон:  from=133, method=4 (friendship), condition=time_night, priority=0
- 700 Сильвеон: from=133, method=4 (friendship), condition=fairy_move, priority=10
- 106 Хитмонли:  from=236, method=1, level=20, condition=atk_gt_def
- 107 Хитмончан: from=236, method=1, level=20, condition=atk_lt_def
- 237 Хитмонтоп: from=236, method=1, level=20, condition=atk_eq_def
- 107 больше не висит на 106 (раньше был ошибочный evolves_from_id=106).
- PRAGMA integrity_check = ok.

ОБРАБОТЧИК
- server/handlers/api/evolution.go:
  checkEvolutionFor(userPokemonID, pokemonID, level) — единая точка выбора ветки.
  - method=1 (level): нужен достигнутый evolution_level + condition (пусто = ок).
  - method=4 (friendship): участвует только при ЯВНО заданном condition, иначе
    legacy-строки не включаются и поведение прочих friendship-видов не меняется.
  - несколько подходящих: ORDER BY evolution_priority DESC, id ASC — выбор стабилен.
  - неизвестный код условия = false (безопасный отказ, без случайной ветки).
  - Atk/Def считаются на целевом уровне по base+IV+EV+nature (utils.CalculateStats),
    а не берутся из устаревших сохранённых колонок.
- checkEvolutionByIDs удалён; applyLevelUp (бой/Леденец) и ручной EvolveHandler
  используют checkEvolutionFor, т.е. одинаковую логику.
- Эволюция Иви происходит на level-up (как friendship в играх) при выполненном
  условии; Тайрог — автоматически на L20.
- Сильвеон приоритетнее дня/ночи, если Иви знает Fairy-атаку (priority=10).
