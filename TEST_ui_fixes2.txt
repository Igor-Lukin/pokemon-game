ФИКС 1 — КНОПКА «ПОКЕДЕКС» В МЕНЮ ПОКЕБОЛА  [СДЕЛАНО, фронт]
--------------------------------------------------------------------
ГРАБЛЯ (расхождение с ТЗ): в DOM карточки команды был ТОЛЬКО id ЭКЗЕМПЛЯРА
(data-pok-id="${p.id}"), а bindBoxLeftEvents проставлял всем .ctx-item именно его.
Species-id в разметке НЕ БЫЛО вообще — если бы взяли data-pok-id, покедекс открылся
бы на СЛУЧАЙНОМ (не том) виде. Поэтому вид проброшен отдельным атрибутом.

СДЕЛАНО (client/static/js/game.js):
  - карточка команды: + data-species-id="${p.pokemon_id}" рядом с data-pok-id
    (та же строка, где .poke.pokemonBoxCard.minimized);
  - bindBoxLeftEvents: читает card.dataset.speciesId и проставляет
    item.dataset.speciesId ВСЕМ .ctx-item (тем же циклом, что и pokId) —
    т.е. механика проброса ровно как у существующего pokId, ничего нового;
  - teamCtxPokedex: TODO заменён на закрытие меню -> closeTeamModal() ->
    openPokedex() -> selectPokemon(speciesId). Гварды: если openPokedex/
    selectPokemon не определены (pokedex.js не загружен) — тихо выходим;
    пустой speciesId -> покедекс просто открывается на списке.

РЕШЕНИЕ ПО КОНФЛИКТУ ПАНЕЛЕЙ (ТЗ разрешало): док команды ЗАКРЫВАЕТСЯ.
Причина: .pokedex-panel — position:fixed, top:0/right:0, width:35%, z-index:1000,
а #team-dock — 616px под иконкой команды, z-index 5 => покедекс физически ложится
поверх дока. Закрываем через существующий closeTeamModal() (не дублируем логику).

ПРОВЕРИТЬ (владелец): покебол у покемона команды -> «Покедекс» -> покедекс открыт
на ЭТОМ виде (имя/статы/картинка), док команды закрылся.

ФИКС 2 — ПОПАП ОПИСАНИЯ СПОСОБНОСТИ  [СДЕЛАНО, фронт + backend]
--------------------------------------------------------------------
УТОЧНЕНИЕ К ТЗ: ТЗ говорит «GetUserTeam берёт имя первой не-скрытой способности
вида» — это УСТАРЕЛО (так было до каркаса [9]). Реально в коде уже подзапрос
`SELECT a.name FROM abilities a WHERE a.id = up.ability_id`, т.е. ФАКТИЧЕСКАЯ
способность ЭКЗЕМПЛЯРА. Описание добавлено ТЕМ ЖЕ подзапросом по up.ability_id =>
требование форвард-совместимости [9] («имя И описание из фактической способности
экземпляра») выполнено УЖЕ СЕЙЧАС, дорабатывать при [9] не придётся.

BACKEND (server/handlers/api/user_pokemons.go, GetUserTeam):
  - структура TeamPokemon: + AbilityDescription string `json:"ability_description"`
    (сразу после AbilityName);
  - SELECT: + COALESCE((SELECT a.description FROM abilities a
              WHERE a.id = up.ability_id), '') as ability_description
    (сразу после ability_name, тот же подзапрос, JOIN не добавлялся);
  - rows.Scan: + &t.AbilityDescription в той же позиции.
  - Сверено вручную: колонок в SELECT 45, аргументов в Scan 45 (совпадает).
  - NULL-безопасно: нет ability_id / NULL description -> COALESCE даёт '' ->
    фронт покажет «Нет описания» (регресса Scan error, как было на gen2, не будет).

ДАННЫЕ (проверено по database/pokemon.db, только чтение):
  - abilities: 220 строк, у ВСЕХ 220 непустое description;
  - у всех покемонов в командах (position 1..6) ability_id ЗАПОЛНЕН (NULL: 0),
    напр. Бурный рост (132 симв.), Мастер залпов (191), Фасеточные глаза (58)
    => попап будет с реальным текстом сразу, доп. подготовка данных не нужна.

ФИКС 3 — ВВОД КОЛИЧЕСТВА ПОЛЕМ (+/- ОСТАВЛЕНЫ)  [СДЕЛАНО, фронт]
--------------------------------------------------------------------
СДЕЛАНО (game.js showQuantitySelector):
  - <span class="inv-qty-value"> заменён на
    <input type="number" class="inv-qty-value inv-qty-input" min="1" max="${maxQty}"
    step="1" value="1"> (класс .inv-qty-value СОХРАНЁН — старые стили не потерялись).
  - Введена ОДНА точка правды setQty(val, writeField): парсит, клампит в [1..maxQty]
    (NaN/пусто/<1 -> 1, >maxQty -> maxQty), обновляет qty, при writeField пишет в
    поле и в ЛЮБОМ случае дизейблит +/- на границах (поведение кнопок как было).
  - +/- зовут setQty(qty±1, true) — те же кнопки, тот же дизейбл.
  - Ввод в поле: setQty(value, false) — значение клампится, но ПОЛЕ на каждом символе
    НЕ перезаписывается. Это осознанно: при перезаписи «на вводе» нельзя набрать
    «100», если maxQty=50 (после «10» поле схлопывалось бы). Приведение поля к
    валидному — на blur и на подтверждении.
  - Enter в поле -> подтверждение (тот же путь, что .inv-qty-confirm).
  - Конфирм: setQty(поле, true) -> overlay.remove() ->
    showPokemonForItemUse(itemId,"candy",qty) — т.е. в бэкенд уходит ТОЛЬКО
    склампленное значение, даже если в поле осталось «9999».
  - Поле получает focus+select при открытии (можно сразу набрать «100»).
  - Клик по полю не всплывает до overlay (иначе закрывался бы селектор).
  - game.css: .inv-qty-input (ширина 90px, бумага/линия/радиус из --pk-*, focus
    сепией) + скрытие браузерных спиннеров (-webkit-appearance/-moz-appearance) —
    свои +/- уже есть.

ПРОВЕРИТЬ (владелец): «100» в поле -> применяется 100 конфет; +/- работают и
дизейблятся на 1 и на максимуме; «0»/«-5»/мусор -> 1; больше наличия -> максимум.
