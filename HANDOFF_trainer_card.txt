1. ЦЕЛЬ И РЕШЕНИЯ ВЛАДЕЛЬЦА
--------------------------------------------------------------------
ЦЕЛЬ: экран/панель «карточка тренера» со всей информацией об игроке.
СОСТАВ (по владельцу):
  1) Шапка: ник; онлайн/оффлайн; регион; СТАТУС (текстовая строка, которую игрок
     пишет сам, напр. «Я никого не боюсь!»); ДОЛЖНОСТЬ (Админ/Гим лидер/
     Полицейский/Наставник и т.п.).
  2) Награды — список. НАГРАДА = отдельный ПРЕДМЕТ с признаком «награда»
     (items.is_award), показываем те, что есть у игрока.
  3) Список ЖЕЛАЕМЫХ покемонов — только ОТОБРАЖЕНИЕ (управления пока НЕ нужно).
  4) Список ДРУЗЕЙ — только ОТОБРАЖЕНИЕ (добавление/удаление — отдельно потом);
     клик по другу открывает ЕГО карточку.
  5) АВАТАР: 2D-картинка, на которую можно надевать одежду (одежда = отдельный
     предмет). В ЭТОЙ задаче — ТОЛЬКО зарезервировать МЕСТО под аватар в карточке
     (заглушка-силуэт). Сам аватар + механика одежды = ОТДЕЛЬНОЕ ТЗ (другой агент).

РЕШЕНИЯ ПО ОБЪЁМУ (владелец подтвердил):
  - Профиль: СВОЯ карточка (редактируемая) + ЧУЖИЕ карточки (read-only).
  - Друзья: только показ (наполнение пока через БД).
  - Желаемые: только показ.
  - Награды: предмет с флагом is_award; показ; выдача через существующий
    /admin/give_item; автовыдача за события — потом.

3. СХЕМА БД (бэкап pokemon.db.bak-before-trainercard ДО правок)
--------------------------------------------------------------------
(1) Поля профиля на users:
      ALTER TABLE users ADD COLUMN status_text TEXT;      -- статус игрока (сам пишет)
      ALTER TABLE users ADD COLUMN role_id INTEGER;       -- должность (FK player_roles), nullable
      ALTER TABLE users ADD COLUMN last_seen TIMESTAMP;   -- для онлайн/оффлайн
      ALTER TABLE users ADD COLUMN avatar_data TEXT;      -- ЗАДЕЛ под аватар (пока не используем)
(2) Должности (справочник + сид):
      CREATE TABLE player_roles (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE);
      INSERT: 1 'Тренер'(дефолт/можно NULL), 2 'Админ', 3 'Гим лидер',
              4 'Полицейский', 5 'Наставник'. (Список расширяемый.)
      (is_admin остаётся флагом ПРАВ; role_id — отображаемая должность, отдельно.)
(3) Награда = предмет:
      ALTER TABLE items ADD COLUMN is_award INTEGER DEFAULT 0;   -- 1 = награда
      (Награды у игрока = user_items, где items.is_award=1. Выдача — give_item.)
      Завести 1-2 тест-награды (category можно 'key_item' или новая 'award'; главное
      is_award=1) и выдать тест-игроку в user_items.
(4) Друзья (симметрично; наполнение пока вручную):
      CREATE TABLE user_friends (user_id INTEGER NOT NULL, friend_id INTEGER NOT NULL,
        PRIMARY KEY(user_id, friend_id),
        FOREIGN KEY(user_id) REFERENCES users(id), FOREIGN KEY(friend_id) REFERENCES users(id));
      (Симметрию поддерживать двумя строками ИЛИ запросом OR — на выбор; показать
       список друзей игрока. Для теста добавить пары вручную.)
(5) Желаемые покемоны (только показ):
      CREATE TABLE user_wishlist (user_id INTEGER NOT NULL, pokemon_id INTEGER NOT NULL,
        PRIMARY KEY(user_id, pokemon_id),
        FOREIGN KEY(user_id) REFERENCES users(id), FOREIGN KEY(pokemon_id) REFERENCES pokemons(id));
      (Для теста заполнить вручную.)
Проверять схему/данные после каждого шага.

5. БЭКЕНД — API И ЗАПРОСЫ
--------------------------------------------------------------------
Новый файл server/handlers/api/profile.go. Структура ответа (JSON) TrainerProfile:
    user_id, username, online(bool), region_name, status_text, role_name,
    is_self(bool), awards[], wishlist[], friends[], avatar(заглушка/пусто).
  где:
    - region_name: JOIN users->locations->regions;
    - role_name: JOIN players_roles по role_id (NULL -> "Тренер" или пусто);
    - awards[]: SELECT items(name,description,image_url) JOIN user_items
        WHERE user_items.user_id=? AND items.is_award=1;
    - wishlist[]: SELECT pokemons(id,name,image_url) JOIN user_wishlist WHERE user_id=?;
    - friends[]: SELECT u.id,u.username, online(u.last_seen) FROM user_friends
        JOIN users u ... WHERE user_friends.user_id=?; (online по last_seen).
Маршруты (routes.go):
    GET  /api/profile           -> ProfileHandler (СВОЯ, is_self=true, редактируемая)
    GET  /api/profile/{id}      -> ProfileHandler (ЧУЖАЯ, read-only, is_self=false)
    POST /api/profile/status    -> SetStatusHandler {text} (ТОЛЬКО своя; trim, лимит
                                    напр. 100 симв.; сохранить users.status_text)
  (Друзья/желаемые/награды — только чтение через /api/profile; отдельных
   мутаций в этой итерации НЕТ.)
ВАЖНО: чужой профиль — read-only (SetStatus только для себя: сверять user_id
сессии с целью). Пароль/почту в ответ НЕ включать.

Награды и бэг: чтобы награды не засоряли обычную сумку 🎒 и не «использовались» —
исключить is_award из инвентаря-сумки (в GetUserInventory или в фильтре бага),
а в карточке показывать отдельным запросом awards[]. UseItem награды не трогает
(effect_type у награды пустой/несъедобный).

6. ФРОНТ — КАРТОЧКА (game.html + game.js + game.css)
--------------------------------------------------------------------
  - Иконка 👤 в шапке (.game-header, рядом с 🎒) открывает СВОЮ карточку
    (док-панель #trainer-dock по образцу #inventory-dock: позиционирование,
    закрытие, стрелка). Загрузка — GET /api/profile.
  - Раскладка карточки (стиль — «Каталог/атлас», как весь UI; токены --pk-*):
      [ЛЕВО] МЕСТО ПОД АВАТАР — фикс. блок (напр. ~200×300) с заглушкой-силуэтом
             (default.png или простой placeholder). Коммент в коде: «сюда встанет
             аватар с одеждой — отдельное ТЗ». Ничего интерактивного.
      [ПРАВО/ВЕРХ] ник; бейдж онлайн/оффлайн (зелёный/серый); регион; должность
             (бейдж role_name); СТАТУС — строка; на СВОЕЙ карточке (is_self) —
             редактируемая (клик -> input -> сохранить POST /api/profile/status),
             на чужой — просто текст.
      [СЕКЦИЯ] Награды: иконки предметов-наград (image_url) + подсказка name/desc.
             Пусто -> «Наград пока нет».
      [СЕКЦИЯ] Желаемые покемоны: мини-иконки покемонов (только показ). Пусто ->
             «Список пуст». Без кнопок.
      [СЕКЦИЯ] Друзья: список ник + бейдж онлайн; КЛИК по другу -> открыть его
             карточку (GET /api/profile/{id}, read-only). Пусто -> «Друзей пока нет».
  - Чужая карточка: то же, но без редактирования статуса и (очевидно) себя-онлайн
    считать по last_seen. Кнопка «назад» к своей — по желанию.
  - Обновление после смены статуса — перезагрузить карточку.
  - Не ломать инвентарь/бой/команду.
