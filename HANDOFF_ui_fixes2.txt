ФИКС 2 — ПОПАП ОПИСАНИЯ СПОСОБНОСТИ В ПОДРОБНОМ ПРОСМОТРЕ [фронт + мелкий backend]
====================================================================
СИМПТОМ: в подробном просмотре покемона способность показана текстом, но по клику
ничего нет. Нужно: клик по способности -> небольшое окно с ОПИСАНИЕМ (как попап
информации об атаке).
КОД:
  - Показ способности: game.js:362 `.divAbility`(<span>${p.ability_name}</span>).
  - Образец попапа: #attack-info-popup + showAttackInfo (game.js:718) — сделать по
    аналогии #ability-info-popup + showAbilityInfo(name, description).
  - Описание способности ЕСТЬ в БД: abilities.description. Но в команду сейчас
    приходит только ability_name (user_pokemons.go GetUserTeam берёт имя первой
    не-скрытой способности вида). ДОБАВИТЬ в тот же запрос/структуру поле
    ability_description (тем же JOIN abilities; description по ТОЙ ЖЕ способности,
    что и ability_name).
СДЕЛАТЬ:
  BACKEND: server/handlers/api/user_pokemons.go GetUserTeam — в SELECT/структуру
    добавить ability_description (COALESCE(a.description,'')) параллельно ability_name
    (тот же подзапрос/JOIN). (Если подробный просмотр берёт данные из ДРУГОГО
    эндпоинта — добавить описание туда же.)
  FRONT:
    - game.html: добавить #ability-info-popup по образцу #attack-info-popup
      (заголовок = имя способности, тело = описание; кнопка/клик-вне закрывает).
    - game.js: .divAbility сделать кликабельной (курсор/hover), на клик ->
      showAbilityInfo(p.ability_name, p.ability_description). Пустое описание ->
      «Нет описания». Позиционировать/закрывать как attack-info-popup.
  ПРИМ.: у покедекс-детали (pokedex.js showPokemonDetail) способность тоже может
    показываться — если там есть клик-цель способности, повесить тот же попап
    (описание из /api/pokedex/.../full, добавить поле при необходимости). Если нет —
    не обязательно.

    Сейчас берём из того же источника, что ability_name — оставить консистентным.

ФИКС 3 — ВВОД КОЛИЧЕСТВА ПРЕДМЕТОВ ПОЛЕМ (+/- ОСТАВИТЬ) [фронт]
====================================================================
СИМПТОМ: при использовании конфет количество набирается только кнопками +/- —
для 100 шт. долго. Хочу вводить число в поле напрямую, но +/- оставить.
КОД: game.js:1318 showQuantitySelector(itemId, maxQty) — сейчас .inv-qty-value это
     <span> с числом + кнопки .inv-qty-minus/.inv-qty-plus, конфирм .inv-qty-confirm
     -> showPokemonForItemUse(itemId,"candy",qty).
СДЕЛАТЬ:
  - Заменить (или дополнить) .inv-qty-value на РЕДАКТИРУЕМОЕ числовое поле
    (<input type="number" min="1" max="${maxQty}"> ИЛИ text с фильтром цифр).
    Кнопки +/- ОСТАВИТЬ — они меняют значение поля.
  - Синхронизация: ввод в поле -> валидировать/клампить в [1..maxQty] (пустое/мусор
    -> 1; больше maxQty -> maxQty); +/- меняют то же значение и обновляют поле;
    дизейбл +/- на границах как сейчас.
  - Enter в поле -> подтвердить (как .inv-qty-confirm). Конфирм берёт значение из поля.
  - game.css: стиль поля в общем стиле селектора количества.
ПРОВЕРКА: ввод «100» в поле применяет 100 конфет; +/- по-прежнему работают; нельзя
выйти за 1..максимум (максимум = количество в наличии).
