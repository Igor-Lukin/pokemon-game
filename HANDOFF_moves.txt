0. КАК РАБОТАЕМ (ритм — НЕ менять)
--------------------------------------------------------------------
Владелец НЕ программист: простой язык, маленькие проверяемые шаги.

На машине диалога (RDP-сервер) Go НЕТ — компилировать нельзя. Ритм:
  1) агент правит .go напрямую на диске проекта (D:\pokemon-game) + меняет
     данные в БД через python+sqlite3 (Go тут нет, но python есть);
  2) пишет TEST_<имя>.txt в КОРЕНЬ проекта (что менялось + чек-лист);
  3) владелец несёт проект на ОСНОВНОЙ ПК (там Go), даёт txt агенту с Go;
     тот делает go build/go vet + сверяет поведение, дописывает отчёт в конец;
  4) владелец говорит «отчёт готов» — читаем отчёт, при ошибках правим.
Каждый TEST = один небольшой шаг/механика. Отчёты пока зелёные = сборка+ревизия
кода (не всегда живой прогон боя — это осознанный нюанс, билд/vet — твёрдый факт).

ВАЖНО: перед каждой правкой БД — бэкап рядом: pokemon.db.bak-before-<что>.
Кодировка при работе с БД из python: sys.stdout.reconfigure(encoding='utf-8').
Через PowerShell в python НЕ слать (BOM ломает stdin) — использовать Bash-героку.

2. МЕТОД КАМПАНИИ
--------------------------------------------------------------------
Идём ОТ АТАК с галкой disabled (не от статусов). Для каждой: читаем описание
из БД -> определяем механику -> если движок уже умеет, чиним ДАННЫМИ; если нет,
пишем КОД (маленькой картой по id) -> снимаем disabled -> TEST.
МЕТРИКА: disabled было 203 -> сейчас 10 (ВСЁ ДОСТУПНОЕ СДЕЛАНО; остаток 10 —
принципиально невозможен без изменения схемы БД, см. §6). (SELECT COUNT(*) FROM attacks WHERE disabled=1)
!!! КАМПАНИЯ ПО АТАКАМ ЗАВЕРШЕНА (по решению владельца). ВСЕ пачки, включая
последние 4 (арены-довесок/Рука помощи/Ароматный шлейф+Левитация/Опережение),
ПРОВЕРЕНЫ на осн. ПК — зелёные. TEST_*.txt вычищены.

Принцип (из старого HANDOFF, соблюдаем): «код по полкам», НЕ data-driven JSON
(отвергнут). Уникальная механика = код, привязка = маленькая карта по id атаки
внутри профильного модуля. Движок боя тонкий.

!!! ГЛАВНЫЙ ГOTCHA — «сентинел power»:
Движок гонит атаку в СТАТУСНУЮ ветку, если (CategoryID==3 ИЛИ power==0). Многие
формульные/особые атаки имеют в БД power=0 -> они «не работали» именно поэтому.
Чтобы урон-атака попала в executeDamagingMove, в БД ставим power=1 (или базовую),
а реальный урон считаем формулой в calculateDamage/movePower. Такие сентинелы
стоят у: 41,222 (половина HP), 336 (вес), 293 (Плевок), 462/453/524/527 (OHKO),
342/305 (Финальный/Психволна), 248 (Захват — по HP цели), 280 (Ночная тень —
= уровень), 351 (Электрошар — по скорости). Не пугаться power у них.
