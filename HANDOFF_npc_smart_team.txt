1. ЦЕЛЬ И РЕШЕНИЯ ВЛАДЕЛЬЦА
--------------------------------------------------------------------
ЦЕЛЬ: у NPC-тренера появляется третий режим команды team_mode='smart' — игра
подбирает команду «с умом» (разнообразие типов, покрытие, баланс ролей), а не
чисто случайно. Настройки бота (запрос владельца): КОЛИЧЕСТВО покемонов и их
УРОВЕНЬ.

РЕШЕНИЯ ВЛАДЕЛЬЦА (2026-07-20):
  - Подход — ЭВРИСТИЧЕСКИЙ взвешенный «драфт» (НЕ ML, НЕ мега-if). Веса —
    константы в коде.
  - Уровень — ФИКСИРОВАННЫЙ (все покемоны бота одного заданного уровня), НЕ
    диапазон, НЕ адаптив к игроку.
  - Настройки СЛОЖНОСТИ (easy/normal/hard) — ПОКА НЕ делаем. Веса фиксированные.

НЕ ДЕЛАЕМ сейчас: сложность/тиры, адаптив к игроку, тематические тренеры
(type_theme), оптимизацию НАБОРА АТАК (атаки берём как в потоке B — generateWildMoves).
Всё это — возможные follow-up, схему под них НЕ переусложнять.

  - pokemons: base_hp, base_attack, base_defense, base_speed, base_special_attack,

  - type_effectiveness(attacking_type_id, defending_type_id, multiplier REAL) —

  - buildNPCTeam(npcID, mode, size, minL, maxL) — ТОЧКА ВСТАВКИ нового режима.
    Сейчас ветки 'fixed' (npc_pokemons) и 'random' (случайные виды). Добавить
    ветку mode=='smart'.
  - buildGenerateFor(pokemonID, level) *WildPokemonGenerate (wild.go) —
    строит покемона заданного вида и уровня (IV/натура/статы + generateWildMoves).
  - wildToBattlePokemon(gen) -> BattlePokemon. Команда врага = []BattlePokemon.
  - Поля npc: team_mode, team_size(1..6), min_level, max_level (от потока A/B).
Админка (поток B): server/handlers/admin/npc.go + npc_form.html — форма NPC с
  выбором team_mode и полями команды; ростер (fixed) в npc_team.go.

4. АЛГОРИТМ УМНОГО ДРАФТА (server/handlers/api/npc_smart_team.go, новый)
--------------------------------------------------------------------
func buildSmartNPCTeam(size, level int) ([]BattlePokemon, error)

(4.1) ПУЛ КАНДИДАТОВ. SELECT видов, у которых есть хотя бы одна УРОН-атака,
      обучаемая к уровню level (по аналогии с generateWildMoves: pokemon_attacks
      JOIN attacks, learn_method_id=1, level_learned_at<=level, a.power>0 и
      a.category_id!=3). Тянуть: id, name, primary_type_id, secondary_type_id,
      base_* статы. Если пул пуст (мало данных) -> ФОЛБЭК: вернуть ошибку, чтобы
      buildNPCTeam откатился на random (см. §5). Дедуп по виду.
      Для покрытия типов заранее загрузить в память карту type_effectiveness
      (attacking->defending->mult), один SELECT.

(4.2) СОСТОЯНИЕ КОМАНДЫ по мере набора:
      - множество занятых видов (без повторов);
      - множество типов, уже представленных в команде (для разнообразия);
      - «наступательный охват»: множество defending-типов, которые команда уже
        бьёт супер-эффективно (mult>1) хотя бы одним STAB-типом своих членов;
      - счётчики ролей (см. классификацию 4.4).

(4.3) СКОРИНГ КАНДИДАТА (сумма взвешенных слагаемых; веса — КОНСТАНТЫ вверху файла,
      с комментарием «ручки настройки»):
      score =
        + W_COVERAGE * (сколько НОВЫХ defending-типов кандидат бьёт супер-эффективно
                        своими STAB-типами, т.е. добавляет к «наступательному охвату»)
        + W_TYPE_DIV * (штраф-бонус за разнообразие: + если тип(ы) кандидата ещё
                        НЕ в команде, − если дублируют уже представленный)
        + W_ROLE     * (бонус, если кандидат закрывает ПУСТУЮЩУЮ роль, см. 4.4)
        + W_STRENGTH * (нормированная сумма base-статов, слабый вес — чтобы команда
                        была живой, но не набивалась одной «мелочью»)
      Рекомендуемые старты весов: W_COVERAGE=3.0, W_TYPE_DIV=2.0, W_ROLE=1.5,
      W_STRENGTH=1.0 (агент может подправить по виду результата; это КОНСТАНТЫ).

(4.4) РОЛИ (классификация вида по доминирующему base-стату):
      - physical  : base_attack — макс;
      - special   : base_special_attack — макс;
      - fast       : base_speed — макс;
      - bulky      : (base_hp+base_defense+base_special_defense)/3 — макс.
      Для команды желательно закрыть РАЗНЫЕ роли; W_ROLE поощряет недостающие.

(4.5) ВЫБОР С УПРАВЛЯЕМОЙ СЛУЧАЙНОСТЬЮ (чтобы команды не были идентичными):
      На каждый слот: посчитать score всем оставшимся кандидатам, отсортировать,
      взять ТОП-K (напр. K=5, тоже константа), выбрать одного ВЗВЕШЕННО-СЛУЧАЙНО
      (вероятность ~ score, либо просто rand среди топ-K). Так «умно», но вариативно.
      Первый слот: топ-K по (W_STRENGTH*сила + небольшой рандом) — семя команды.

(4.6) СБОРКА: для каждого выбранного вида — gen := buildGenerateFor(id, level);
      wildToBattlePokemon(gen) -> добавить в team. Гарантировать len>=1 и >=1
      боеспособного (HP>0). Вернуть team.
      ВНИМАНИЕ (инвариант потока B): EnemyTeam строится ОДИН раз и НЕ append-ится
      после — buildSmartNPCTeam возвращает готовый срез, дальше его не трогают.
