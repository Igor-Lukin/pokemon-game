================================================================
ЗАДАНИЕ НА ТЕСТ: Фаза 2 (A) — условные изменения статов по погоде
pokemon-game
================================================================
В отличие от Фаз 0/1 (чистый рефакторинг), тут ЕСТЬ намеренное новое
поведение: атака "Отростки" (Growth, id=9) должна давать +2 к Атаке и
СпАтаке В СОЛНЦЕ и +1/+1 при любой другой погоде. Для ВСЕХ ОСТАЛЬНЫХ
атак поведение НЕ должно измениться.
Собери, проверь оба пункта, впиши отчёт внизу.

----------------------------------------------------------------
1. ЧТО ИЗМЕНИЛОСЬ
----------------------------------------------------------------
Механизм: у строки изменения стата появилось условие погоды.
  БД: в таблицу attack_stat_changes добавлена колонка
      req_weather INTEGER NOT NULL DEFAULT 0
      (0 = любая погода; иначе строка срабатывает только при этой погоде;
       id погоды: 2 солнце, 3 дождь, 4 град, 5 буря).
      (Колонка уже добавлена в рабочую БД database/pokemon.db; также
       добавлена в CREATE TABLE в server/db/database.go для свежих БД.)

  server/handlers/api/battle.go:
    - в struct StatChange добавлено поле ReqWeather int;
    - loadStatChanges читает req_weather (COALESCE 0);
    - applyStatChanges получил параметр weatherID и пропускает строку,
      если sc.ReqWeather != 0 && weatherID != sc.ReqWeather;
    - параметр weatherID протянут в applyStatChanges и executeDamagingMove
      через ВСЕ вызовы (передаётся bs.BattleWeatherID). Изменились сигнатуры:
        func applyStatChanges(attacker, defender, move, weatherID, round, log)
        func executeDamagingMove(attacker, defender, move, weatherID, round, log)

  Админка (server/handlers/admin/attacks.go + templates/admin/attack_form.html):
    - StatChangeRow + load/save/parse получили ReqWeather;
    - в форме атаки у каждой строки "Изменение стата" добавлен выпадающий
      список "Погода" (Любая/Солнце/Дождь/Град/Буря), поле sc_req_weather.

  Данные "Отростки" (id=9) в attack_stat_changes:
      базовые:  (stat 1 Атака +1, любая), (stat 4 СпАтака +1, любая)
      бонусные: (stat 1 Атака +1, солнце), (stat 4 СпАтака +1, солнце)
    Итог: в солнце строки складываются -> +2/+2; иначе -> +1/+1.
    (Складывание работает, т.к. StatStages += stages по каждой строке.)

НЕ трогалось: applyEffectByID (наложение статусов), карточки статусов
из Фаз 0/1, общий помощник conditionMet (остаётся заготовкой, не вызван).

3. ЭТАЛОН ПОВЕДЕНИЯ
----------------------------------------------------------------
A) РЕГРЕСС (не должно измениться): любая атака с изменениями статов,
   где req_weather=0 у всех строк (это ВСЕ существующие атаки, кроме
   Отростков-бонусов) — работает точно как раньше, при любой погоде.

B) НОВОЕ (Отростки, id=9), статусная атака (category 3):
   - без солнца (нет погоды / дождь / град / буря):
       Атака +1, СпАтака +1;
   - в солнечную погоду (BattleWeatherID = 2):
       Атака +2, СпАтака +2.
   Проверяется по ступеням статов (StatStages[1] и StatStages[4]) и по
   сообщениям в логе ("Атака <Имя> повышена!" и т.д. — по одному на
   каждую сработавшую строку; в солнце строк по стату две -> два
   сообщения на стат, суммарно +2).

----------------------------------------------------------------
4. КАК ПРОВЕРИТЬ
----------------------------------------------------------------
A) Диффом: подтвердить, что при req_weather=0 условие пропуска никогда
   не срабатывает (поведение старых атак не меняется), и что weatherID
   действительно приходит из bs.BattleWeatherID во всех вызовах.
B) Боем: взять покемона с Отростками.
     - применить без погоды -> +1/+1;
     - выставить солнце (атакой, вызывающей солнечную погоду, либо
       временно через БД/тест) и применить Отростки -> +2/+2.
   Также прогнать любую другую стат-меняющую атаку и убедиться, что она
   не изменилась.

Тонкости:
  - Ступени статов ограничены диапазоном [-6..+6] (клип не изменился).
  - В солнце обе строки на стат складываются в один и тот же StatStages,
    двойной клип не должен ничего ломать (+1 затем +1).
  - Если у покемона уже +6 — потолок, лишнее не добавится (как и раньше).
